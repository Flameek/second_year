# Отчетик

---
Сгенерированы данные варианта: четыре типа массивов (случайный, отсортированный, обратный, с дубликатами) по пять размеров с геометрическим шагом от 1000 до 100000. Общее количество файлов — 20.

#### Реализованы четыре алгоритма:

- array_sum — сумма элементов массива. Один проход по массиву, сложность O(n).

- array_max — поиск максимума. Один проход, сложность O(n).

- count_equal_pairs — подсчёт пар равных элементов. Двойной цикл, сложность O(n²).

- binary_pow — бинарное возведение в степень по модулю. Метод квадрирования, сложность O(log n).

---
#### Аналитические оценки

| Алгоритм | Сложность | Обоснование |
|----------|-----------|-------------|
| `array_sum` | O(n) | n сложений, один проход |
| `array_max` | O(n) | n-1 сравнений, один проход |
| `count_equal_pairs` | O(n²) | n(n-1)/2 сравнений, двойной цикл |
| `binary_pow` | O(log n) | число итераций равно числу битов показателя |

#### Результаты замеров

Наклоны графиков в осях log-log:

| Алгоритм | Теоретическая оценка | Фактический наклон |
|----------|---------------------|-------------------|
| `array_sum` | O(n) | 1.023 |
| `array_max` | O(n) | 0.982 |
| `count_equal_pairs` | O(n²) | 1.989 |

Наклоны совпадают с теоретическими оценками. Небольшие отклонения объясняются накладными расходами интерпретатора Python, кэш-эффектами процессора и фоновыми процессами операционной системы.

Для бинарного возведения в степень график зависимости времени от log₂ n близок к горизонтальной прямой, что подтверждает оценку O(log n).

#### Почему log-log неинформативен для логарифмического алгоритма

Время работы растёт как log n. В осях log-log это выглядит как log(log n) — функция, которая растёт крайне медленно. График становится почти горизонтальной линией, и по наклону невозможно судить о порядке роста. Поэтому для бинарного возведения используется график t(log₂ n) в линейных осях — там O(log n) даёт прямую.

#### Почему замер выполняется по модулю

Без модуля числа в Python становятся огромными из-за длинной арифметики. Умножение больших чисел не является операцией O(1), и время начинает зависеть от длины чисел, а не от числа итераций алгоритма. С модулем 1000000007 числа остаются маленькими, и замер показывает именно сложность O(log n).
