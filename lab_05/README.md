# СиАОД · ЛР №5. Двоичное дерево поиска

Вариант 39. Seed 69. Паспорт прежних лабораторных в data/generated не менялся.

## Реализация

Итеративный спуск использует сравнение с ключом узла. Вставка игнорирует дубликаты. При удалении листа ссылка становится пустой. У узла с одним ребёнком ссылка заменяется ребёнком. Для узла с двумя детьми берётся преемник: минимум правого поддерева. После переноса ключа преемник отсоединяется с сохранением его возможного правого ребёнка.

Три глубинных обхода рекурсивные. В ширину используется очередь deque. Высота измеряется в рёбрах (−1 для пустого дерева), размер считает узлы.

## Верификация

Прошли шесть оригинальных групп самопроверки, включая три случая удаления и сверку с set/sorted. Независимый тест Academic Executor дополнительно проверил 2000 случайных изменений с seed 69: размер, in-order и поиск после каждой операции. [Протокол](verification.txt)

Черновик реализации подготовлен с помощью Codex. Исходный проверочный блок преподавателя сохранён отдельно от BST: добавлен импорт BST. Итоговые замеры запущены в Bubblewrap. Для защиты нужно самостоятельно воспроизвести удаление узла с двумя детьми.

## Сложность и вывод

Вставка, поиск и удаление занимают O(h) времени, где h — высота. В данной серии рост высоты заметно медленнее роста n. Случайный порядок вставки в среднем даёт логарифмическую высоту, но обычное BST не гарантирует её. При упорядоченной вставке высота n−1, а поиск и изменение могут занимать O(n). Список использует линейный поиск O(n). В сбалансированном AVL высота логарифмическая и имеет асимптотическую верхнюю оценку около 1,44·log₂(n) с поправкой на определение высоты и константу.

Обходы посещают O(n) узлов. Рекурсивные обходы используют O(h) стека, а обход в ширину — память порядка ширины фронта.
