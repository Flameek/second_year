# СИАОД · ЛР №5. Подготовка к защите

Вариант 39, seed 69. Для демонстрации запусти
`python3 lab_05/lab05-bst-completed.py --variant 39`. Сначала идут проверки,
потом замеры. Большая точка занимает несколько десятков секунд.

1. **Как работают обходы?** In-order (лево, узел, право) выдаёт ключи BST по
   возрастанию. Pre-order (узел, лево, право) показывает корень каждого
   поддерева перед потомками. Он полезен при сохранении структуры дерева.
   Post-order (лево, право, узел) обрабатывает детей раньше родителя.
   Это подходит для освобождения узлов или вычислений снизу вверх.
   Level-order начинает с корня. Каждый обработанный узел добавляет детей
   в конец очереди.
2. **Почему удаление через преемника сохраняет порядок?** Минимум правого
   поддерева больше всех ключей слева и меньше остальных ключей справа.
   У преемника нет левого ребёнка. Когда его прежний узел удаляют, ссылка
   его родителя должна указывать на правого ребёнка преемника, если он есть.
   Пример: вставки `50, 30, 70, 60, 80, 65`, затем `delete(50)`.
   Новый ключ корня — 60, левым ребёнком 70 становится 65.
   Ожидаемый pre-order: `[60, 30, 70, 65, 80]`.
3. **От чего зависит сложность?** Спуск идёт по одной ветке. Для удаления
   с двумя детьми ещё ищется минимум справа. Суммарная длина пути ограничена
   высотой дерева. Время `O(h + 1)`. Для цепочки из n узлов `h = n − 1`.
4. **Что даёт AVL?** Высоты поддеревьев узла различаются не больше чем на
   единицу. Вставка или удаление могут нарушить баланс, который
   восстанавливается поворотами. Высота `O(log n)`, верхняя оценка
   `1,44 log₂(n) + O(1)`. Повороты сохраняют порядок ключей.

На проверке понимания проследи удаление листа, удаление узла с одним ребёнком
и удаление корня. Затем объясни, почему проверка `set/sorted` выявляет потерянные
и дублированные ключи, а проверка формы pre-order различает способы замены.
Объясни, зачем обоим контейнерам передавать одинаковые запросы, исключать
первый прогрев и брать медиану. Для отчёта используй [фактические замеры](README.md#бенчмарк).
